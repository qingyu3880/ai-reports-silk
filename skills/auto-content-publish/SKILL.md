# 全自动内容发布系统

## ⚠️ 核心原则：宁缺毋滥，绝不含糊

**严格禁止：**
- ❌ 推送简版内容
- ❌ 发送道歉说明充数
- ❌ 质量不达标勉强推送

**唯一准则：**
要么生成符合L4+深度标准的完整内容，要么静默失败等待下次重试。

## 触发条件

当用户或定时任务需要执行以下任一内容发布时：
- AI日报生成与发布
- 音乐推荐生成与发布
- 图书推荐生成与发布
- 电影推荐生成与发布
- 航空AI周报生成与发布

## 强制流程（必须严格执行）

```
生成内容 → 质量检查 → 保存文件 → 推送到对话 → 同步网站 → 完成
   ↑___________________________________________________|
   （任何一步失败，立即停止，禁止跳过，禁止推送简版）
```

## 质量检查（新增关键步骤）

在推送之前，必须检查：

### AI日报质量标准
- [ ] 字数：3000-4000字
- [ ] 结构完整：核心洞察 + 深度分析 + 范式转移 + 今日行动
- [ ] 深度解读 ≥200字
- [ ] 战略影响 ≥150字  
- [ ] 行动建议 ≥100字
- [ ] 航空高管视角

### 音乐/图书/电影质量标准
- [ ] 字数：音乐≥2000字，图书/电影≥2500字
- [ ] 查重通过（无历史重复）
- [ ] 版本对比完整
- [ ] 进阶路径清晰
- [ ] 航空业关联分析
- [ ] **包含可直接访问的链接**

**任何一项不达标 → 删除文件 → 记录失败 → 静默结束（不推送）**

**核心原则：宁缺毋滥。绝不推送简版。**

### 检查清单

|------|---------|---------|---------|
| 8:30后 | 音乐推荐 | recommendations/music/YYYY-MM-DD* | 如文件存在且质量达标→推送；否则静默 |

| 12:30后 | 定制日报 | reports/daily-custom-YYYY-MM-DD.md | 如文件存在且质量达标→推送；否则静默 |
| 17:30后 | 图书推荐 | recommendations/books/YYYY-MM-DD* | 如文件存在且质量达标→推送；否则静默 |
| 20:30后 | 电影推荐 | recommendations/movies/YYYY-MM-DD* | 如文件存在且质量达标→推送；否则静默 |

### 补发流程（严格版）

**发现未推送的内容：**
1. 读取文件内容
2. **质量检查**：确认字数、结构、深度符合标准
3. 如质量达标 → 推送到对话（附补发说明）
4. **如质量不达标 → 删除文件，静默失败**

**发现文件不存在：**
1. **绝不补生成简版**
2. 静默记录缺失
3. 等待主任务下次定时重试

**严禁：
- 绝不生成简版充数
- 绝不发送道歉说明代替内容
- 绝不在质量不达标时推送**

### 连续失败告警

如果同一内容连续3次尝试都失败：
1. 暂停该内容的自动任务
2. 向用户发送告警：
   > ⚠️ **[内容类型]连续失败通知**
   > 
   > 原因：[AI服务过载/网络错误/其他]
   > 建议：手动检查或等待服务恢复

### 记录与追踪

每次补发记录到：`logs/resend-YYYY-MM-DD.md`
```
[时间] 补发 [内容类型]
- 原因：[原任务失败/文件未找到/其他]
- 状态：[成功/失败]
- 备注：
```

## 执行前检查

1. 确定内容类型和日期
2. 检查目标目录是否已有当天文件
3. 如果已存在 → 读取并直接推送，跳过生成
4. 如果不存在 → 执行完整流程

## 强制步骤详解

### 步骤1：生成内容
- 使用子代理(sessions_spawn)生成内容
- 子任务必须包含：生成 + 保存 + 推送 + 同步 的完整指令
- 等待子任务完成

### 步骤2：保存文件（强制验证）
- 文件必须保存到指定路径
- 保存后立即读取验证文件存在且大小 > 1KB
- 验证失败 → 报错停止

### 步骤3：推送到对话（强制验证）
- 读取文件内容
- **使用 message 工具推送到当前对话**
- **禁止依赖子任务自我报告，主代理必须亲自验证**
- 推送后确认用户可见
- **禁止假设"同步网站=完成"，必须显式推送**

**关键修复：**
- 子任务完成 ≠ 内容已推送
- 子任务报告"已推送"可能是误判
- 主代理必须在子任务完成后，亲自读取文件并推送

### 步骤4：同步网站（强制验证）
- 运行 sync_reports.py
- 验证 reports.json 已更新
- 验证网站可访问（如配置）

## 关键修复点（防止音乐推荐类错误）

### 错误模式识别
**问题：** 子任务报告"已推送"，但实际未到达对话
**原因：** 子代理可能将"同步网站"误判为"推送完成"
**后果：** 用户收不到内容，但系统认为已完成

### 修复方案
1. **子任务只负责：生成 + 保存 + 同步**
2. **主代理负责：读取文件 + 推送到对话**
3. **禁止子任务自我报告推送状态**

### 新流程图
```
定时任务触发
    ↓
主代理检查今天是否有文件
    ↓
如果没有 → 启动子任务（生成+保存+同步）
    ↓
子任务完成返回
    ↓
主代理读取生成的文件
    ↓
主代理推送到对话（使用message工具）
    ↓
完成
```

### 验证清单
- [ ] 子任务不包含"推送到对话"指令
- [ ] 子任务完成后，主代理必须读取文件
- [ ] 主代理必须使用message工具推送
- [ ] 推送后确认内容可见
- [ ] **质量检查通过（字数、结构、深度）**

## 失败处理（严格版）

### 生成失败
- 记录失败标记到 logs/failed-YYYY-MM-DD-[类型].md
- **静默失败，不推送、不道歉、不凑合**
- 等待下次定时任务重试

### 质量不达标
- 删除已生成的不达标文件
- 记录失败原因
- **静默失败，不推送简版**
- 等待下次重试

### 推送失败
- 记录失败标记
- **不发送道歉说明**
- 等待售后检查任务补发（仅当文件存在且质量达标时）

### 连续失败告警
如果同一内容连续3次失败：
1. 暂停该内容的自动任务
2. 发送告警通知用户
3. 等待人工介入

**核心原则重申：**
- ❌ 绝不推送简版
- ❌ 绝不发送道歉说明充数  
- ❌ 绝不在质量不达标时推送
- ✅ 要么完整高质量内容，要么静默失败等待重试
